Preview -> Payment -> Business Facts -> Questions -> Audit -> Report

### Landing Page
- User learn about Nuave
- Input one official website, public Instagram business profile, or Google Maps
  business listing. TikTok is not supported in this touchpoint.
- User click "Audit bisnis saya"


### Preview Page
- User see a preview of his business crawled from his website/Instagram/Tiktok/GBP account:
	- Business logo
	- Business name
	- Summary of the business
- Decision: user can continue the audit process by paying **Rp99.000 total**.
  Nuave adds no tax or fee at checkout, and the unpaid preview remains valid
  for 30 days.
	- Input email
	- Click "Bayar"

### Payment Page
- Midtrans offers QRIS, bank transfer, GoPay, and DANA
- System send a payment instruction to email
- System show payment instruction
- Page showing which email this payment is tied to
- After payment done, the user redirected to the confirmation page

### Confirmation page
- Confirm the payment is successful
- User can proceed to audit, "Lanjutkan audit"

### Business information page
- System will fetch and generate business information page based on what it knows (crawl + AI model):
	- Business website/Instagram/Tiktok (first input, editable, mandatory)
	- Business logo (auto generated, can be removed by user)
	- Business name (crawled, editable, mandatory)
	- Summary of business (generated by AI, editable, not mandatory)
	- Products/services (generated by AI, editable, not mandatory)
	- Unique selling proposition (or key differentiators? or both?)(generated by AI, editable, not mandatory)
	- Competitors (generated by AI, editable, not mandatory
	- )
- User click "Selanjutnya"

### Prompt draft page
- List of proposed prompts:
	- Unbranded questions
		- 2 needs discovery
		- 2 solution discovery
		- 1 comparison
	- Branded questions
		- 1 comparison
		- 2 validation
		- 2 actions
- User can go back to the business information page but this prompt will be saved
- **Jalankan audit** opens the final **Mulai audit sekarang** confirmation. This
  action consumes the one paid audit; do not use credit or token language.
### Loading page
- Showing list of prompts being asked and its status (not processed, in process, done)
- Showing loading animation in each prompt
- Showing time elapsed
- When the evidence set reaches 10/10 evaluable observations, hand it to
  `06 — Audit Report`. Do not celebrate processing completion because the
  report may contain unfavorable evidence.
### Audit report page
- Governed by [`06-audit-report.md`](./06-audit-report.md).
- Shows the direct overall appearance count and score out of ten, for example
  **4/10**, then separates **Tanpa menyebut bisnis Anda** from **Menyebut bisnis
  Anda** so the overall count is not mistaken for spontaneous discovery.
- Shows the main result, key findings and other businesses mentioned, one to
  five evidence-backed actions, all ten questions and their evidence, and the
  method and limitations.
- The primary action is **Download PDF**. The web report and dedicated PDF
  layout use the same report facts, evidence, actions, and version.
- If PDF generation fails, deliver the validated web report and show the PDF as
  temporarily unavailable while Nuave retries it from the same report version.
- This module sends the report-ready email and owns delivery failure and resend.

### Report Access and Recovery — later

A later module owns private access opening, another-device return, expired or
revoked access, and recovery. Do not choose an account, dashboard, OTP, magic
link, or password architecture until that module is specified. The mechanism
must use finite founder-approved retention and private, revocable access.
