## Problem

**Evidence.** On 2026-09-19 the founder completed the new audit journey once,
end to end, in a browser on a local machine: entered business → live fact
preparation → confirmed facts → ten questions generated by GLM 5.3 Flash
("direct-ten" method) → one question edited → explicit approval → ten grounded
observations → one report → JSON and PDF downloads → Back/reload kept the
report. 13 provider requests, about USD 0.17, no retries.

**Interpretation.** The journey works, but it is wired as a founder-local
experiment and cannot run on the deployed site:

1. The public entries still run the old workflow: `v2.nuave.ai → /audit`
   opens it directly, and the landing hero (`LandingAuditHero.tsx`) embeds the
   old identity/checkout steps and then navigates to
   `/audit/v2?entry=landing-paid`. The new flow lives only at
   `/audit/new-intake`, starts on a fixture business, and is titled as a trial.
2. The new question route and the new-method run/report routes refuse whenever
   the build is a production build (`NODE_ENV === "production"`), regardless
   of configuration.
3. The single-send protection for GLM generation depends on files on a local
   disk (frozen intake + `attempt.consumed`), and the freeze step has no UI.
   Cloudflare Workers has no such disk.
4. Live execution of observations needs a separate local-only flag; the GLM
   credential is not part of deployed configuration.
5. The shared API routes still accept the legacy question methods (`run` and
   `report` default an omitted `question_method` to `canonical`;
   `glm-questions` accepts `glm-slots`), so archiving pages alone would leave
   paid legacy paths reachable.
6. The old flow, its routes and its tests remain in the build and must keep CI
   green if removed.

## Desired outcome

Anyone who opens `https://v2.nuave.ai` can run the whole new journey for a
real business exactly as it ran locally on 2026-09-19, ending with the same
web report and working JSON/PDF downloads. The journey is **publicly
accessible during the founder trial**, protected only by basic per-IP rate
limits, the existing per-request ceilings, and one switch that turns the whole
audit off. The old flow is no longer reachable and its code is archived.

**Accepted risk (founder decision 2026-09-19):** the site is public with no
login. Each complete journey costs ≈ USD 0.17–0.35 of provider usage. The
protections below reduce bursts and accidents; they are not a hard spending
cap and do not stop a determined abuser. The founder monitors provider
billing during the trial and can flip the switch off.

## User and situation

The founder testing the product on the real deployment, and any visitor who
finds the URL. No payment, no accounts, no customer delivery yet.

## Scope

- Make the new journey the `/audit` entry and the only audit flow on the site,
  including the landing hero.
- Replace the local-only guards with deployed configuration: one on/off
  switch and a server-selected live/synthetic mode.
- Replace the disk-based single-send protection with per-IP rate limits using
  the Cloudflare pattern the site already has, with limits the platform
  supports.
- Reject legacy question methods at the shared API routes.
- Make the JSON export and the on-page notice carry accurate call counts and
  costs, including GLM attempts.
- Archive the old flow (pages, components, API routes, tests) so the build,
  `npm run verify` and CI stay green.
- One pull request, deploy through the existing CI, one authorized live test.

## Non-scope

- **Authentication of any kind** (login, access code, Google/Supabase,
  CAPTCHA, invitations). Founder decision: too distracting now.
- Report content, format, classification or usefulness (AC-08 of Spec 009) —
  deferred by the founder until this spec is verified.
- Accounts, payment, customer delivery, e-mail, dashboards, history,
  server-side storage of sessions or reports, databases.
- A true server-owned spend ledger or a hard billing cap (the client-supplied
  ledger and the USD 5 accounting guard are retained as they are).
- Durable recovery of an interrupted request across devices or after the
  browser session is lost.
- Any change to the audit engine, the direct-ten question instruction, models,
  providers or prices.
- Redesign of intake screens beyond removing trial/fixture framing.

## Experience

**Start.** `https://v2.nuave.ai/audit`, and the landing page's audit
call-to-action, open the new intake directly at the **business name + source
URL** step with empty fields — no fixture business, no "Uji coba" title (page
title "Audit visibilitas AI | Nuave" or the existing product title). A short
Indonesian line states this is a trial version and results apply to the tested
sample only (existing wording may be reused).

**Main path.** Identical to the verified local journey: prepare facts (live
identity fetch + one live extraction) → review/confirm → generate ten
questions (one live GLM 5.3 Flash call) → edit freely → explicit approval →
visible progress over ten observations → one report → "Cetak / simpan PDF"
and "Unduh bukti JSON". Back and reload keep settled inputs and the finished
report and never start another paid stage.

**Completion.** The report page as it exists today (with the 2026-09-19
width fix), downloads working from the normal controls. The report notice
states how many real provider calls were made and the accounted cost.

**Switched off.** Every audit page shows "Audit tidak tersedia saat ini." and
every audit API route answers `404` before any provider work.

## Requirements

**Switch and mode**

- **R-01 One switch.** `NUAVE_NEW_AUDIT_ENABLED` (`"true"`/`"1"`) serves the
  journey and the five API routes (`identity`, `extract`, `glm-questions`,
  `run`, `report`). Default off → `404` for those routes and the "tidak
  tersedia" page. The check runs first, before body parsing, rate limiting,
  credentials or provider work.
- **R-02 Server-selected mode.** `NUAVE_AUDIT_MODE` = `"live"` or
  `"synthetic"`, chosen by server configuration only; no request parameter
  can change it. `live` requires the provider credentials (`OPENCODEGO_API_KEY`
  etc. as today) and `CHEAPERINFERENCE_API_KEY`; if any is missing the
  affected stage stops with a clear error naming the stage (never the secret)
  and **does not** fall back to synthetic. `synthetic` runs the existing
  labeled substitutes (offline tests, local development). Production deploy
  sets `live`. The visible "Audit lokal — jawaban sintetis" notice appears in
  `synthetic` and never in `live`. The three local-only conditions
  (`glmExperimentEnabled`, `glmLiveRequested`, `auditLiveExecutionAuthorized`)
  and every `NODE_ENV !== "production"` check on these routes are removed;
  tests that asserted "production always 404" are rewritten to assert
  "switch off → 404" and "mode synthetic → substitutes, zero provider calls".
- **R-02a Legacy methods rejected.** `run` and `report` accept **only**
  `question_method: "direct-ten"`; an omitted method no longer defaults to
  `canonical` and is rejected with `400` before parsing the rest of the body.
  `glm-questions` accepts only `direct-ten` (`glm-slots` → `400`). The legacy
  code paths for `canonical`/`glm-slots` are archived with the old flow
  (R-08), not left dormant behind a flag.
- **R-02b Check order** on every request to the five routes: switch →
  method accepted → rate limit → mode/credentials → body validation →
  provider work.

**Burst protection on Cloudflare (low-hanging fruit only)**

- **R-03 Per-IP rate limits.** Use the existing Cloudflare rate-limit binding
  pattern (`AuditRateLimitBinding` in `src/lib/audit/rate-limit.ts`, keyed by
  `CF-Connecting-IP` as `extract` already does). Add three bindings, all
  **period 60 seconds** (the only supported periods are 10 and 60 s; limits
  are approximate and per Cloudflare location):
  - `GLM_CALLER_RATE_LIMITER` — limit **2** per minute (question generation);
  - `AUDIT_RUN_CALLER_RATE_LIMITER` — limit **2** per minute;
  - `AUDIT_REPORT_CALLER_RATE_LIMITER` — limit **3** per minute (one report,
    one retry, one report after a resumed run fit within the window).
    Existing `identity`/`extract` limiters stay. A limited request returns
    `429` with "Terlalu banyak permintaan, coba lagi dalam beberapa menit."
    and makes no provider call. If a binding is unavailable in production the
    route fails closed (`503`), as `extract` does today; in `synthetic` mode
    without bindings (local `next dev`) the limiter is a no-op that logs once.
- **R-04 Existing ceilings stay.** Per request: extraction ≤ 2 calls,
  observations ≤ 3 attempts per question and ≤ 30 total, report ≤ 3 calls per
  workflow, accounted session ceiling USD 5 via the client-supplied ledger.
  The client keeps its existing locks: one generation per approved fact
  revision, controls disabled while a request is in flight, no duplicate run
  from repeated clicks, Back/reload never start a paid stage.
- **R-05 No disk on Cloudflare.** Remove the requirement that a live GLM send
  be preceded by a disk-frozen attempt. The frozen-attempt/`attempt.consumed`
  code path is kept only behind `NUAVE_GLM_EVIDENCE_DIR` for local evidence
  runs and must not be required, or attempted, when that variable is unset.
  Nothing on the deployed routes writes to the filesystem.

**Honest recovery for question generation**

- **R-06 Generation attempts and interrupted state.** The server holds no
  session, so a generation whose response never reached the browser (tab
  closed, network drop, timeout) cannot be "shown again". Behavior:
  - the client records every generation attempt it started in its session
    (`started_at`, outcome `succeeded` / `failed` / `interrupted`, execution
    `confirmed` / `unknown`, and the provider-reported cost when the response
    carried one — GLM responses include `usage.cost`; a failed HTTP response
    without usage records `cost: null`, labelled "biaya tidak diketahui");
  - an attempt that gets no response shows an honest interrupted state:
    "Permintaan pembuatan pertanyaan terputus. Pertanyaan mungkin sudah
    dibuat dan mungkin sudah dikenai biaya, tetapi tidak diterima." with one
    explicit button "Buat pertanyaan lagi" that is a **new paid attempt**
    (subject to R-03/R-04) — never an automatic retry;
  - a successful pack is stored in the browser session as today and reload
    shows it without a request.
- **R-07 Export and notice carry real totals.** The JSON export
  (`Unduh bukti JSON`) is extended so that:
  - `provenance.generation` holds the successful pack's `requested_model`,
    `returned_model`, `response_id`, `transport`, `billed_cost_usd`,
    `model_mismatch` (all present today in the session's pack `generation`);
  - `provenance.generation_attempts` lists every attempt from R-06 with its
    outcome and cost (or `null`);
  - each prompt carries `original_question` (generated text) and
    `edited: boolean`; the exact approved text stays in `question`;
  - `provenance.provider_calls` counts **confirmed** real calls only:
    preparation, observations, report, and GLM attempts that returned a
    response — success or HTTP failure (the 2026-09-19 export showed 12; the
    correct figure was 13). Requests rejected before provider work (switch
    off, method `400`, rate-limit `429`) count as zero calls and zero cost;
  - `provenance.uncertain_attempts` counts generation attempts whose
    execution is unknown (`interrupted` — the response never reached the
    browser), so an uncertain call is never silently folded into or dropped
    from the confirmed total;
  - `provenance.accounted_cost_usd` is the sum of preparation + run + report
    accounted costs **plus** every known GLM attempt cost, with
    `provenance.unknown_cost_attempts` giving the number of attempts whose
    cost is unknown;
  - existing keys and the customer-facing stripping of telemetry in
    `makeCustomerEvidenceExport` are unchanged.
    The report page's notice in `live` mode shows the same `provider_calls`
    and `accounted_cost_usd` (four decimals, labelled as an application
    estimate) and, when > 0, the counts of uncertain and unknown-cost
    attempts.

## Evidence, data, privacy, and cost

- Only public business information enters prompts; visitor IPs are used only
  as rate-limit keys inside Cloudflare and are never logged by the app,
  stored, or included in the export.
- No raw provider bodies stored server-side; the JSON export is the evidence
  and is downloaded to the visitor's machine.
- Cost per complete journey ≈ USD 0.17–0.35 (2026-09-19 basis). Public access
  is an accepted founder risk for the trial; per-IP limits, per-request
  ceilings and the switch bound bursts and accidents, not a determined abuser.
  The accounted USD 5 guard is an accounting check, not a supplier billing
  cap. Secrets are set in Cloudflare by the founder, never committed.
- Live test on the deployed site needs a fresh founder authorization sentence
  naming the business (same convention as Spec 009).

## Acceptance criteria

- **AC-01 Switch off.** Given `NUAVE_NEW_AUDIT_ENABLED` unset, when `/audit`,
  `/` → call-to-action, or any of the five API routes is requested, then the
  "tidak tersedia" page / `404`, and zero provider calls (offline tests
  assert no fetch to provider hosts).
- **AC-02 Legacy methods.** `POST /api/audit/run` and `/report` with
  `question_method` omitted, `"canonical"` or unknown → `400` before body
  parsing; `POST /api/audit/glm-questions` with `"glm-slots"` → `400`; zero
  provider calls.
- **AC-03 Entry.** When a visitor opens `/` and follows the call-to-action,
  the new intake opens on empty business fields with product page title and
  no fixture or trial-fixture wording; `/audit/new-intake` redirects to
  `/audit`; `/audit/v2` is `404`.
- **AC-04 Same journey.** In `synthetic` mode, the existing `new-intake-glm`
  e2e scenarios still pass (question edit carry-through, approval, ten
  observations, report, JSON download, Back/reload with no duplicate
  run/report request).
- **AC-05 No disk.** Given `NUAVE_GLM_EVIDENCE_DIR` unset, when a GLM
  generation is requested in `live` mode with the provider stubbed, then no
  filesystem call is attempted (unit test with `node:fs/promises` mocked to
  throw) and the request proceeds.
- **AC-06 Rate limits.** Given the limiter reports `limited`, when
  `glm-questions`, `run` or `report` is requested, then `429` with the
  Indonesian message and zero provider calls; given the limiter is unavailable
  in production mode, `503` and zero provider calls. A run followed by a
  report and one report retry within one minute is **not** limited.
- **AC-07 Interrupted generation.** Given a generation request whose response
  is dropped by the test harness, the client shows the R-06 interrupted state,
  records the attempt as `interrupted` with `cost: null`, sends no automatic
  retry, and "Buat pertanyaan lagi" sends exactly one new request.
- **AC-08 Export totals.** A unit test on a synthetic session with one failed
  GLM attempt (with usage cost) followed by a successful one asserts:
  `provenance.provider_calls` = preparation + 2 confirmed GLM attempts +
  observations + report; `provenance.accounted_cost_usd` = sum of accounted
  costs + both GLM costs; `provenance.generation_attempts.length === 2` with
  correct outcomes and `execution` values; a second case drops the response
  of the first attempt, then succeeds on retry, and asserts the dropped
  attempt appears in `uncertain_attempts` (not in `provider_calls`) while the
  confirmed retry is counted; a third case asserts a rate-limited `429`
  attempt adds zero calls and zero cost;
  `provenance.generation.*` match the successful pack; the edited prompt has
  `edited: true` and `original_question` equal to the generated text; existing
  observation keys (`prompt_id, category, branded, question,
instruction_version, system, requested_model, returned_model, response_id,
observed_at, raw_answer, run_status, sources`) unchanged. The report
  notice renders the same two totals.
- **AC-09 Archive.** No file under `src/` imports from `archive/`; `/audit/v2`,
  `/api/audit/prompts`, `/api/audit/variance` return `404`; `AuditRunStep`
  still renders in the new flow; `npm run verify` and CI `validate` pass.
- **AC-10 Workers runtime.** `npm run test:workers` (R-10a) passes, or its
  local run output is attached to `VERIFICATION.md` with the reason CI could
  not run it.
- **AC-11 Deployed live test (founder judgment).** Given the merged deploy and
  a fresh founder authorization, when the founder runs one real business
  through `v2.nuave.ai`, then the journey completes with 13 ± retries
  provider requests, the report and both downloads work, the notice shows the
  call count and cost, and the export's `provider_calls`,
  `accounted_cost_usd` and `generation_attempts` are written to this
  package's `VERIFICATION.md`. Report usefulness is **not** judged here.
